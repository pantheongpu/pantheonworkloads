# Real GPU against its simulated counterpart

Generated by `tools/sim_vs_gpu.py` (`bin/pw coverage --write`) from the files in `docs/data/sim-vs-gpu/`; do not edit by hand. Every value below is a row of those files, and each row names its source (a document and section, or a workflow run, artifact and commit). `bin/pw coverage --check` fails in CI when this page and the data differ.

## How to read this

- **pantheonsim has no timing model.** It is a functional simulator: it says whether a simulated GPU gives the same answers as a real one, never how fast the real one is. Its wall-clock is CPU time on whatever host ran it. Table 2 shows that time as the cost of simulating, not as GPU performance, and no simulated number is placed beside a real throughput. `bin/pw` still refuses benchmark metrics on `sim:` targets; this page does not change that.
- **Parity** means: the same workload, checked against the same reference with the same tolerance, gives the same verdict on the real card and on the simulated one, and the deviations from the reference are of the same size. It does not mean the simulated card is as fast, and PASS on both sides only says both stayed inside the tolerance.
- **Pairing.** Each real NVIDIA card is paired with the simulated profile that pantheonsim characterized on that part (pantheonsim `nvidia/docs/profiles.md`): the A10G (AWS g5, sm_86) with `sim:nvidia/a10g`, the T4 (AWS g4dn, sm_75) with `sim:nvidia/t4`, the L4 (AWS g6, sm_89) with `sim:nvidia/l4`, the L40S (AWS g6e, sm_89) with `sim:nvidia/l40s`. Workloads with a real and a simulated result: A10G 14, T4 14, L4 14, L40S 14. The other simulated profiles are shown as PASS / FAIL / SKIP columns for the same A10G workload (`a10` is the generic A10, a different profile from `a10g`); "not run" means no result exists, not a pass.
- **Same reference and tolerance** is checked from the repository, not assumed: the real run and the simulated run used workload directories that are identical (manifest, `reference.json` and scripts) between the two commits named in the data, except where the row says otherwise. Where the real rerun and a scheduled nightly run on main used the same commit, that is the basis (the same commit, so the same files). The simulated results are the newest scheduled nightly run on main named in the data sets below, except `l4`, which is a pull-request run (the profile was added to the matrix by the change that added this comparison, so no scheduled run has it yet).
- **Never estimated.** An empty cell is a value the sources do not hold. Real wall-clock seconds exist only for the workloads of the real reruns (56 (card, workload) series, 168 runs, each one a row of `real_runs.tsv`); a workload outside them has an empty real cell and no ratio.
- **Software.** The real reruns (A10G, T4, L4, L40S) and the nightly simulation used the same libraries: torch 2.14.1+cu130, torchvision 0.29.1 and transformers 5.18.0 (the version the references were recorded with; the older real records of 2026-10-08 used 5.19.0 for the arch-* workloads and are marked superseded where the rerun replaces them).
